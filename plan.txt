================================================================================
                        RASHKOGIE GTA - ARCHITECTURE DIAGRAM
================================================================================

An AI system that learns to play GTA V by watching you play, then improves
via Monte Carlo Tree Search during live gameplay.


================================================================================
1. HIGH-LEVEL PIPELINE
================================================================================

  +-----------+      +------------+      +-----------+      +------------+
  |  CAPTURE  | ---> | TOKENIZE   | ---> |   TRAIN   | ---> |  MONITOR   |
  | (you play)|      | (BPE vocab)|      | (4 stages)|      | (dashboard)|
  +-----------+      +------------+      +-----------+      +------------+
       |                                       |                    |
       v                                       v                    v
  JSONL files              Frozen modules feed downstream     Real-time charts
  (state + controls)       stages in strict order            + param hot-reload

3. TRAINING PIPELINE (Strict Sequential Stages)
================================================================================

  Stage 1: encoder_intuition        Stage 2: reward_head
  +--------------------------+      +--------------------------+
  | Trains: encoder +        |      | Trains: reward MLP       |
  |         intuition head   |      | Data: state pairs ->     |
  | Data: state_t -> state_t+1      |        realized return   |
  | Loss: MSE < 0.05        |      | Loss: MSE < 0.1         |
  | FREEZES after converge   | ---> | FREEZES after converge   |
  +--------------------------+      +--------------------------+
                                              |
                                              v
  Stage 3: action_planner           Stage 4: metacontroller
  +--------------------------+      +--------------------------+
  | Trains: planner MLP      |      | Trains: MCTS policy      |
  | Data: (z_t, prev) ->    |      | Data: live gameplay +    |
  |       player's token     |      |       search decisions   |
  | Loss: CE, acc > 60%     |      | Loss: REINFORCE (PG)     |
  | Depends: stages 1-2     | ---> | Depends: stages 1-2      |
  +--------------------------+      +--------------------------+

  Orchestrator: coordinator.py
  Config:       training_config.json
  Status:       training_status.json

5. TOKENIZER (BPE Control Vocabulary)
================================================================================

  Raw controls per frame:
    u_steer (-1..1), u_throttle (0..1), u_brake (0..1)
           |
           v
  Quantize: 8 bins per axis (0-7)
           |
           v
  BPE merge frequent adjacent pairs
           |
           v
  ~870 tokens in lookup table
    token_id -> { control_chunk, frame_count, duration }
           |
           v

================================================================================
6. MCTS FRAME LOOP (Live Agent in GTA)
================================================================================

  metacontroller/frame_loop.py

  +---------------------------------------------------------------------+
  |  While current token is playing (~20 frames per token):             |
  |                                                                     |
  |  Each Frame:                                                        |
  |    1. executor_frame()                                              |
  |       - Send 1 control frame to GTA (named pipe)                   |
  |       - Read game state                                            |
  |       - Encode -> z_t                                              |
  |       - Compute realized reward (ground-truth formula)             |
  |                                                                     |
  |    2. search_step()                                                 |
  |       - MCTS picks ONE decision:                                   |
  |         EXPLORE   -> expand child, descend                         |
  |         ROLLBACK  -> go back to parent, try sibling                |
  |         COMMIT    -> lock in best_path[0], stop search             |
  |         INTERRUPT -> abort token NOW, execute best immediately     |
  |                                                                     |
  |    3. metacontroller MLP                                            |
  |       - Input: time_context + search_state                         |
  |       - Output: action logits -> sample decision                   |
  |                                                                     |
  |  When token ends:                                                   |
  |    - next_token = search_tree.best_path[0] (or planner fallback)   |
  |    - trainer.train_step(realized_returns, decisions)                |
  |    - Emit metrics to JSONL                                         |
  +---------------------------------------------------------------------+

10. KEY DESIGN DECISIONS
================================================================================

  - Shared z_t [128]: One embedding used by ALL downstream modules
  - Strict stage ordering: Each stage freezes before next begins
  - Lookup-table tokenizer: No learned embeddings, just BPE over controls
  - Per-frame MCTS: One search decision per GTA frame (not per token)
  - Ground-truth reward formula: Separate from learned reward_head
  - JSONL streaming: Training writes metrics; dashboard polls + ingests
  - Hot-reload params: Browser edits config, training picks up next step
  - Dual WebSocket: Browser clients + training clients on separate pools
  - SQLite WAL mode: Concurrent reads during collector writes

12. SEARCH TREE EXPANSION (per node)
================================================================================

  Parent node (z_parent)
       |
       | For each candidate token_j:
       v
  +------------------------------------------+
  | 1. Intuition Head rolls token:           |
  |    merged_token_500 -> unmerge ->        |
  |    [base_12, base_7, base_3]             |
  |    z_parent -> z_1 -> z_2 -> z_3        |
  |    = z_child                             |
  |                                          |
  | 2. Reward Head scores transition:        |
  |    reward_head(z_parent, z_child,        |
  |      rf_parent, rf_child, duration,      |
  |      time_left) -> r_edge               |
  |                                          |
  | 3. Action Planner populates child:       |
  |    action_planner(z_child, prev_token)   |
  |    -> [token_A, token_B, token_C]       |
  +------------------------------------------+
       |
       v
  Child node: { z_child, r_edge, candidates, N=0, W=0, Q=0 }
